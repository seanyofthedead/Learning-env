## How to protect quality when comparing proposals

Give each bidder the same event plan: about 185 guests, buffet/BBQ/family style, hosted beer and wine with soft drinks, same ceremony/cocktail/reception sequence, setup/strike hours, and the locked dates in order. Keep budget targets internal.

Compare these items explicitly rather than assigning unsupported service scores:

- Food: tasting, menu quantities, dietary provision, buffet replenishment and service duration.
- Staffing: named lead, staff count, paid arrival/departure times, bussing, table setup, flip, cleanup and overtime. Do not make labor the first cut.
- Bar: hours, bartender count, alcohol, ice, water, soft drinks, glassware, licensing, insurance and last call. A two-hour golf bar or three-hour package is not automatically equivalent to a wedding evening.
- Rooms: 185 seated at rounds with dancing retained, heated indoor ceremony/holding plan, separate cocktail space and exclusive access where needed. The cocktail requirement itself does not explicitly require indoor use; still request a November weather plan.
- Bill: venue/room/minimum charges, rentals, linens, delivery/late pickup, cake/cutting, getting-ready access, parking, required security, service charge, taxes and mandatory gratuity. Confirm whether service charge is distributed as gratuity.

A hall proposal should identify who is responsible for every task. A package proposal should identify every exclusion. Retain the $2,000 tips allocation until its use is reconciled with the actual contract; a service charge is not automatically a tip.

## Savings that must not be counted twice

1. **The original trims are already in the budget.** The $9,069 original reduction, buffet/beer-and-wine format, day-of-only planning and excluded extras cannot be added again as new savings.
2. **Included standard rentals are already removed from package models.** Furniture, china, basic linens, dance floor and cake cutting are not a second credit. Specialty linens/chargers are a separate locked $935 line; changing that design would be a new optional choice, not a free saving.
3. **A complete caterer bill may overlap the separate allowances.** If its quote includes china, basic linens, setup, delivery, cake or cutting, remove the matching separate modeled line once, not the entire rental stack automatically. Keep enough actual service coverage.
4. **A hotel night is not a getting-ready suite.** A confirmed included stay might replace the existing $600 wedding-night line; it does not prove early access or eliminate a separate prep allowance.
5. **An included venue coordinator may not replace the couple's coordinator.** Keep $2,500 until responsibilities, rehearsal, assistant, hours and end-of-night coverage genuinely match. Any eventual saving stays within the overall caps unless the couple explicitly reallocates it.
6. **Vendor meals and gratuities need reconciliation, not duplication.** The existing $400 vendor-meal allowance is outside the envelope. A proposal that includes those meals should replace that provision once. Likewise, establish whether any mandatory gratuity overlaps the existing tips plan.
7. **Free parking is only a saving after confirmation.** Onsite parking alone does not establish it. The Old Hickory examples retain $1,110.
8. **Quote ceilings and zero-rent sensitivity rows are not prices.** An unpublished venue at $0 plus catering is only a subtotal. Hypothetical package prices chosen to hit $32,139 provide no evidence of affordability.
9. **The reserve is never a funding source.** Headroom under the venue envelope is additional unallocated room, not permission to spend the reserve or raise another category silently.

## Reproduce these comparisons

Run the following from the repository root. This uses the existing saved specs and evaluates in memory; it does not change any model or scenario file. The fee adjustment avoids escalating a nominal 2027 all-in allowance twice when an older venue rate is used. Existing model tests and source files remain authoritative.

```python
import copy, json, math, sys
from pathlib import Path
sys.path.insert(0, "wedding/budget")
import wedding_budget_model as m

root = Path("wedding/output/specs")
examples = [
    ("Oak", "value_scenarios/oak_room_catering_100.json", None, 1000),
    ("Gathering", "value_scenarios/gathering_place_catering_100.json", None, 5000),
    ("Heritage", "value_scenarios/ag_center_catering_100.json", None, 4000),
    ("Villa", "package_venues/the_villa_beltsville.json", 105, 2000),
    ("Crowne", "package_venues/crowne_plaza_college_park.json", 100, 2000),
    ("Old Hickory", "package_venues/old_hickory_gc.json", 105, 2500),
]

def evaluate(spec):
    spec = copy.deepcopy(spec)
    if spec.get("outside_catering"):
        spec["outside_catering"] = m.Catering(**spec["outside_catering"])
    return m.evaluate(m.Venue(**spec), 185)["all_in"]

for name, path, package_pp, fees in examples:
    spec = json.loads((root / path).read_text())
    if package_pp is not None:
        spec["package_pp"] = package_pp
    uplift = 1.04 ** max(0, 2027 - spec.get("price_year", 2027))
    spec["other_fees"] = spec.get("other_fees", 0) + fees / uplift
    venue = evaluate(spec)
    spending = venue + m.nonvenue_total(185, trimmed=True)
    print(name, venue, round(spending, 2), round(32139 - venue, 2))

for name in ["the_villa_beltsville", "crowne_plaza_college_park", "old_hickory_gc"]:
    spec = json.loads((root / "package_venues" / (name + ".json")).read_text())
    spec["other_fees"] = 1500
    low, high = 1.0, 200.0
    for _ in range(50):
        spec["package_pp"] = (low + high) / 2
        if evaluate(spec) <= 31139:
            low = spec["package_pp"]
        else:
            high = spec["package_pp"]
    print(name, "ceiling", math.floor(low * 100) / 100)
```
